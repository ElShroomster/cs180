Part 2: Basic Alignment

First, we were required to implement basic image alignment techniques, namely euclidean distance and normalized cross correlation. To implement these techniques, we had to search a small radius of displacements to find a match with the smallest loss value.

For the purposes of this assignment, I searched a 30 by 30 pixel square of offsets to find the point with the least loss value. This meant, I searched range(-15, 15) in the x-direction and range(-15, 15) in the y-direction. To implement the Euclidean distance metric, I just returned np.linalg.norm(a - b) where a and b are the color channels. For NCC, the formula was a little more complicated, since I had to divide each channel by the norm of each, unroll it into a list instead of a 2-d vector, then compute the dot product.

There are a couple small issues with this basic alignment. Firstly, the cross correlation uses reuglar pixel values, and we know that different channels might not have the same brightness or intensity. Additionally, it is possible that we run into errors with scenes with more of one color than another. To fix this first issue, I had the idea of taking a Sobel edge detection filter in order to cross correlate the images. Essentially, I'd take an edge detected filtered image as inputs to the existing euclidean distance functions. Here is the before and after of some images that improved through this edge detection method.

The image definitely gets more clear, but there is still quite a bit of room for improvement. I also noted that edge cropping also caused issues with the cross correlation, especially since edges are very bright, adding a lot to the norm. Temporarily cropping these before calculating the correlation edges further improved the accuracy:

The second issue is that this alignment takes too long, especially on higher quality images. An ad-hoc solution I used temporarily is to only scan a random subset of the image and compute the cross correlation of this random subset. This rapidly improved scan times, however it also introduced some theoretical noise that I didn't really see through experimentation, however it's quite clear that it exists. Part 3: Advanced Alignment

Unfortunately, the previous methods for speed improvement are very ad-hoc. Additionally, they don't help very much with accuracy either. To fix this, first I implemented an image processing pyramid. At a high level, this algorithm scans down-sampled versions of the images for offsets, gradually increasing them. What this does is allow us to scan less individual offsets, think of it as binary search.

The way I implemented the image pyramid was simple. First, I took downsampled the image all the way until it was at most 32x32 in size. Then, I checked an offset of radius 5 to find the overlap with the least norm. This was especially prone to outliers, so I also added a minor edge-detecting method using Sobel filters as a bell and whistle. However, with the baseline implementation, I then upsampled the image by a factor of 2 (also doubling the scanned offset), and checked a 5x5 pixel radius from there, all the way until we hit the maximum size of the image. At each level, I would use NCC to calculate the loss.

Here are some images that improved using this method. Additionally, all of the images took under 5 seconds to render, a massive improvement from over a minute.

This was amazing, however I felt like I was running into a bunch of walls, especially with the methods used for cross correlation and comparison. Using knowledge from CS 184, I knew that you could correlate images using phase through a fast fourier transform. Using this knowledge, I implemented the phase_correlation function by hand to have a much better correlation metric. Additionally, this would be super fast, since we just need to compare the displacement of phase peaks, rather than scan an image through numerous offsets. This also takes care of issues with differing brightness and color values in the different channels.

The calculation of phase correlation was pretty simple. All I had to do was use np.fft.fft2 to convert the images into the fourier domain. Then, I just had to scan for the peaks in both channels, and calculate the offset between the location of these two values, and that is the shift for best phase correlation. I will note that sometimes this causes issues, especially since it's prone to outliers.
